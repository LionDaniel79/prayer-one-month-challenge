# 커뮤니티 화면·첨부 수정 운영 안내

## 회원 화면과 관리자 화면
`/community`는 관리자가 로그인했어도 회원 화면입니다. 폴더 관리와 이동 버튼은 표시하지 않습니다. 본인이 작성한 게시글의 수정·삭제만 표시합니다. 관리자가 다른 성도의 글을 수정할 수 없도록 서버도 작성자를 검사합니다.
`/admin/community`는 폴더 생성·이름 변경·순서 변경·삭제, 게시글 이동·삭제를 위한 화면입니다. 자신의 글을 포함하여 게시글 수정은 제공하지 않습니다. 본인 글을 수정하려면 회원 화면으로 이동합니다. 다른 사람의 글 삭제는 전용 관리자 API에서 처리합니다.

## 게시판 순서
관리자 → 커뮤니티 관리 → 폴더 관리에서 위로/아래로 버튼을 누르면 즉시 저장됩니다. 첫 게시판의 위로, 마지막 게시판의 아래로 버튼은 비활성화합니다. 회원 화면도 같은 순서로 표시됩니다. 다른 창에서 순서나 폴더가 변경되면 최신 목록을 다시 불러오고 재시도를 안내합니다. 기존 폴더와 게시글은 삭제하지 않습니다.
폴더 안의 전체 폴더 링크는 목록 위 한 곳만 남깁니다. 첫 화면의 폴더 아이콘과 이름은 같은 줄에 표시합니다.

## 사진
첨부된 사진은 게시글 제목/작성 정보 다음, 본문 앞에 표시합니다. 본문과의 간격은 본문 두 줄 높이입니다. 서버가 실제 이미지 데이터를 확인해 1920px 이하 WebP 미리보기를 만들며 원본 다운로드는 보존합니다. 로그인이 필요하며 공개 이미지 최적화 서비스나 공개 버킷으로 전달하지 않습니다.
JPG/PNG/WebP/GIF/AVIF/TIFF와 서버가 해독할 수 있는 HEIC/HEIF를 대상으로 합니다. HEIC 지원은 서버 디코더에 따라 달라집니다. 손상됐거나 지원되지 않는 사진은 다운로드 안내를 보여줍니다. SVG/HTML 등의 실행 문서를 이미지처럼 직접 표시하지 않습니다. 사진 미리보기는 백신 검사가 아닙니다.

## 첨부 수정
회원 화면 → 본인 게시글 → 게시글 수정에서 기존 첨부 제거와 새 파일 추가를 할 수 있습니다. 기존 유지 파일과 새 파일을 합해 최대 2개, 파일당 6MB(6,291,456바이트)입니다. 삭제·추가·제목·본문은 수정 저장 성공 시 하나의 트랜잭션으로 반영됩니다. 첨부 교체 중 오류가 나면 공개된 원래 글과 파일은 그대로 유지됩니다.
수정 중 새 파일은 별도 비공개 공간에 512KiB 단위로 전송합니다. 길이·순서·SHA-256이 맞아야 저장됩니다. 서버가 저장했지만 응답이 유실된 경우 같은 수정 화면에서 다시 저장해도 중복 적용하지 않습니다. 다른 창에서 글이 바뀌었으면 덮어쓰지 않고 충돌을 안내합니다. 이때 입력을 복사한 뒤 새로고침합니다. 새로고침한 브라우저는 로컬 파일 선택을 복원할 수 없습니다.
수정 취소는 미반영 변경만 제거합니다. 이미 저장된 글을 취소 동작으로 지우지 않습니다. 게시글 ID·댓글·좋아요는 첨부 수정과 관계없이 보존합니다. 미완료 수정은 회원당 최대 3개이며 만료 정리는 다음 수정 시작 시 수행합니다. 별도 정기 삭제 작업은 없습니다.

## 배포
추가형 migration은 `drizzle/20260928152600_community_refinement.sql`입니다. 기존 글/첨부/댓글/좋아요를 지우지 않습니다. 새 파일 스테이징도 기존 서버 전용 DATABASE_URL을 사용하므로 새 비밀값이 필요하지 않습니다.
검증은 일회용 DB의 가상 계정으로 실행하며 실제 회원 데이터는 변경하지 않습니다. 현재 배포 대상은 기존 공유 Preview이며 main 병합 여부와 구분해서 보고합니다. 새로운 `/community-release.json` 표식을 통해 이전 배포가 아닌 개선판이 공유 주소에서 실제 제공되는지 확인합니다.
