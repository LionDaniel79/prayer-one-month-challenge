# 커뮤니티 운영 안내

회원 메뉴의 커뮤니티는 공지 바로 위에 있습니다. 기본 자유게시판을 제공하고 폴더에 들어가면 최신 게시글 목록, 검색, 페이지 이동, 글쓰기가 나옵니다. 게시글 상세에는 첨부파일, 좋아요와 댓글이 표시됩니다.

회원은 본인 글·댓글을 수정/삭제할 수 있습니다. 관리자는 폴더 생성/이름 변경, 게시글 이동, 모든 글/댓글 수정·삭제가 가능합니다. 폴더 삭제는 미완료 글까지 포함해 비어 있을 때만 가능하며 마지막 폴더는 남깁니다. 게시글 삭제는 첨부·댓글·좋아요도 삭제하며 복원 기능은 제공하지 않습니다. 기존 글 이동은 첨부와 댓글·좋아요를 보존합니다.

좋아요는 회원당 게시글마다 하나입니다. 다시 누르면 취소되며 목록·상세에 개수가 표시됩니다. 좋아요 회원 명단은 노출하지 않습니다.

## 파일과 실패 복구
파일당 6MB(6,291,456바이트), 게시글당 최대 2개입니다. 512KiB 조각으로 전송하며 원본 크기와 SHA-256이 일치해야 게시글이 등록됩니다. 전송 중에는 화면을 유지하고 실패하면 같은 작성 화면에서 다시 등록합니다. 입력과 선택한 파일은 그 화면에 유지됩니다.

새로고침 후에는 브라우저 보안상 선택한 로컬 파일을 복원하지 않습니다. 첫 화면의 내 미완료 글에서 내용을 확인하고, 업로드가 완료된 글은 등록 마무리를 누를 수 있습니다. 일부 전송만 된 글은 삭제 후 원본 파일로 다시 작성합니다. 미완료 글은 회원당 최대 3개, 24시간 경과 후 다음 글 생성 시 정리됩니다. 별도의 정기 삭제 작업은 아직 없습니다.

작성 취소/미완료 글 삭제는 서버에서 초안 상태를 잠금과 함께 확인합니다. 동시에 등록이 성공한 글을 미완료 정리로 지우지 않습니다. 명시적 게시글 삭제는 별도 기능입니다.

파일은 인증된 API를 통해서만 내려받으며 웹 실행 문서/실행 파일의 주요 확장자는 차단합니다. 이는 백신 검사가 아닙니다. 신뢰할 수 있는 작성자의 파일만 열고, 내려받은 파일은 기기 보안 프로그램으로 확인하십시오.

## DB와 용량
기존 `DATABASE_URL` 외에 추가 비밀값은 필요하지 않습니다. 첨부파일 원본을 비공개 PostgreSQL bytea 조각으로 저장하므로 DB 용량과 백업 크기에 포함됩니다. 최대 크기 파일 2개를 매번 올리면 게시글 100개에 원본만 약 1.2GiB가 필요합니다. 이는 산술상 최대치이며 인덱스/DB 부가 공간과 실제 압축 효과는 별도입니다.

Supabase 프로젝트의 DB 사용량을 확인하고 서비스 요금제의 용량 기준 전에 정리/증설 계획을 세웁니다. 데이터가 많아지면 비공개 오브젝트 저장소로 첨부 모듈을 옮기는 것이 다음 확장 단계입니다. 실제 내용 없이 용량만 확인하는 SQL:

```sql
select pg_size_pretty(pg_database_size(current_database())) as database_size;
select pg_size_pretty(pg_total_relation_size('prayer_app.community_file_chunks')) as attachment_table_size;
```

모든 community 테이블은 RLS 활성/공개 역할 권한 회수입니다. 앱 자체 서버 세션과 관리자/작성자 검사를 거칩니다. API 응답은 private, no-store입니다.

## 배포와 되돌리기
`drizzle/20260928130024_community_board.sql`은 기존 테이블을 변경하지 않는 추가형 migration입니다. 기존 서비스 브랜치 배포 전에 한 번 적용합니다. 배포 오류 시 이전 Vercel 배포로 되돌리되 community 테이블/데이터를 삭제하지 마십시오. 삭제형 rollback은 사용하지 않습니다.

자동 검사는 일회용 DB의 가상 사용자만 사용합니다. 실제 회원/공지/기도/심방 데이터로 시험 게시글을 만들거나 삭제하지 않습니다. Preview 배포 성공과 인증된 실기기 확인을 구분해 기록합니다.
