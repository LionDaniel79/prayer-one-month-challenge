# 관리자 대시보드와 활동 집계

회원 메뉴는 공지 → 기도운동 → 심방신청 → 기도요청 → 커뮤니티 → 목양지 순서입니다. 목양지는 권한이 있는 계정에만 보입니다. 관리자 메뉴는 대시보드 다음에 공지 관리, 기도운동 관리 순서로 표시합니다.

## 사용자 수와 기도운동 참여자는 다른 지표입니다

- 전체 등록 사용자: 사용자 관리의 성도 명단 전체 인원입니다. 아직 로그인하지 않은 명단도 포함합니다.
- 활성 사용자: 그 명단 중 한 번 이상 정상 로그인한 사람입니다. 최근 접속 여부나 기도 체크 횟수가 아닙니다. 로그아웃해도 활성 이력이 사라지지 않습니다.
- 비활성 사용자: 정상 로그인 이력이 없는 사람입니다. 미리 생성된 계정만 있고 로그인하지 않았다면 비활성입니다.
- 로그인 허용/제한은 별도의 보안 설정입니다. 활성 사용자라도 로그인 제한을 걸 수 있으며 이 경우 명단에 ‘활성 · 로그인 제한’으로 표시합니다.
- 기도운동 참여: 현재 설정한 도전의 기간 안에서 오늘까지 유효한 기도 체크가 하나 이상 있는 사용자입니다. 다른 도전/기간 밖/미래/일요일의 기록은 포함하지 않습니다. 기존 도전별 참여자 제외와 로그인 제한 정책은 유지합니다. 여러 번 체크해도 한 사람으로 셉니다.

기도운동 관리의 맨 아래 ‘기도운동 탭 활성화’를 해제하고 저장하면 모든 회원 메뉴에서 기도운동이 숨겨집니다. 같은 관리 화면의 참여자 명단·샘별 통계도 숨겨지고 API에도 해당 명단을 반환하지 않습니다. 재활성화하면 보존된 체크 기록으로 다시 집계합니다. 사용자 활성 상태와 원래 기록은 바뀌지 않습니다.

## 목양지 미확인

제출 완료된 목양지 중 관리자가 아직 해당 버전을 확인하지 않은 건수입니다. 작성 중인 초안은 제외합니다. 카드에서 ‘미확인 목양지만 보기’로 이동합니다.

관리자가 **관리자 → 목양지 관리의 상세 화면**을 정상적으로 열면 확인 상태를 저장합니다. 목록 미리보기, 회원 화면 열람, API GET 또는 TXT/사진 다운로드만으로는 확인 처리하지 않습니다. 모든 관리자에게 공통인 확인 상태이며, 실제로 본 버전만 확인됩니다. 통신 실패 시 미확인을 유지하고 ‘확인 다시 저장’ 버튼으로 재시도합니다.

제출본의 수정 저장이 완료되어 새 버전이 되면 다시 미확인으로 집계합니다. 수정 초안만 만들거나 취소한 경우에는 확인 상태가 바뀌지 않습니다. 삭제된 제출본은 집계와 최근 활동에서 빠집니다. 확인 처리는 본문·첨부·작성자·제출일시·버전을 바꾸지 않습니다.

## 최근 활동

공지 발행, 심방 신청 상태, 기도요청, 완료된 목양지 제출을 최신순으로 표시합니다. 한 페이지에 최대 10개이며 ‘다음’으로 오래된 항목, ‘이전’으로 새로운 항목을 확인합니다. 시간이 같은 항목도 안정적으로 정렬합니다. 목양지 항목을 누르면 해당 제출본의 관리자 상세 화면으로 이동합니다. 기도요청 본문, 심방 사유, 목양지 입력 내용·첨부는 활동 목록에 포함하지 않습니다.

‘이번 주 확정 심방’ 카드와 공지 건수 카드는 제거했습니다. 심방은 대기 건수만 남고, 공지의 발행 활동은 최근 활동에 계속 표시합니다.

## 기존 설치 갱신

추가형 마이그레이션 `drizzle/20261007010000_admin_dashboard_metrics.sql`을 새 코드 배포 전에 한 번 적용합니다. 새 설치는 기존대로 전체 SQL을 파일명 순서대로 적용합니다. 이미 적용한 SQL은 재실행하지 않습니다.

기존 최초 로그인은 보관된 세션 생성 이력의 가장 이른 날짜로 복원합니다(만료·로그아웃 세션 포함). 로그인 증거가 없는 사전 생성 계정은 임의로 활성 처리하지 않습니다. 기존에는 목양지 확인 이력을 저장하지 않았으므로 기존 완료본은 첫 관리자 확인 전까지 미확인으로 표시됩니다. 기존 성도·기도·목양지 본문·Google 연결 자료나 비밀값은 바꾸지 않습니다.
