# 접수 Gmail 알림 구현·검증 메모

## 범위
목양지의 최종 제출, 정상 Google Calendar 동기화가 끝난 심방신청, 새 기도요청에 한 줄 Gmail 알림을 추가합니다. 과거 기록·수정·미완성 업로드는 대상이 아닙니다. 개인정보 본문과 첨부는 이메일·큐에 넣지 않습니다. 상세 사용·설정 안내: [접수 이메일 알림](../email-notifications.md).

## 사용자 승인이 필요한 부분
관리자 대시보드 아래 ‘접수 이메일 알림’에서 본인 Gmail 연결, 확인 메일 전송, 알림 사용 저장을 직접 완료해야 합니다. 배포만으로 메일 발송이 켜지지 않습니다. 기존 Calendar 연동과 ChatGPT의 Gmail 연결은 웹앱에 gmail.send 권한을 주는 절차를 대신하지 못합니다. Gmail API 활성화 및 Google의 필요한 OAuth 검증도 운영자가 확인합니다.

## 설계와 검토
- 같은 DB 트랜잭션에 최소 큐 데이터를 저장하고, 응답 후 작업과 비밀 인증 Cron으로 발송합니다.
- 프로덕션 런타임이 설정한 transaction-local DB 값이 있어야 새 알림을 만들 수 있습니다. Preview/CI는 같은 DB를 연결하더라도 알림을 만들지 않습니다.
- 발송 승인 상태와 Calendar 승인 상태는 별도 쿠키·일회용 DB 상태·PKCE·용도별 암호화로 구분합니다. 저장한 수신 이메일과 서명 검증된 Google 계정이 일치해야 합니다.
- 발송 직전에 현재 설정과 관리자 권한을 재검사합니다. 접수 큐와 설정 비활성화는 DB 잠금으로 직렬화합니다. 이미 전송이 시작된 항목은 취소하더라도 도착할 수 있습니다.
- 확실한 일시 거절과 발송 전 통신 실패는 제한적으로 재시도하지만, 메시지 전송 후 결과가 불분명한 항목은 unknown으로 보류합니다. 정확히 한 번 배송을 보장하지 않습니다.
- 대기 개인정보는 7일, 최소 상태 이력은 30일 후 정기 작업에서 정리합니다. 오래된 원본을 재동기화해 이력 정리 후 다시 메일을 만드는 것을 차단합니다.

## 확인한 개발 단계
- 새 provider가 없는 상태의 신규 검사 실패(RED)를 확인한 뒤 구현했습니다.
- 새 DB/API/UI가 없는 상태에서 브라우저 검사를 추가하고 이후 전체 구현을 적용했습니다.
- 후보 7c26868의 CI 38053577609: 단위·정책·lint·build·일회용 TLS DB 및 브라우저 93개 통과. 이 결과는 후보 버전 검증이며 이후 최종 변경의 배포 검증을 대체하지 않습니다.
- 추가 검토에서 설정 취소/큐 생성의 경쟁 조건과 이력 보관 후 과거 이벤트 재발송 가능성을 보완하고 테스트를 추가했습니다.
- 기존 심방 테스트는 실행 날짜에 의존하던 테스트에만 명시적 기준일을 넣었습니다. 실제 심방 신청 날짜 정책은 바꾸지 않았습니다.
- 실제 회원 로그인·기도요청·목양지·심방 데이터를 시험 생성/삭제하거나 Calendar 토큰을 변경하지 않습니다.
