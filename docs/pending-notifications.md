# 미처리 공동체 알림 API

`GET /api/admin/notifications?page=1`은 기존 56사랑 관리자 세션으로만 조회한다. 기존 대시보드의 최근 활동 API는 그대로 유지한다. 목회 보조앱이 새 API를 사용하며 비밀값이나 DB 구조 변경은 필요 없다.

포함: 기도 접수·기도중, 심방 신청·확정, 제출 완료되고 현재 버전이 미확인인 목양지. 제외: 기도 완료, 심방 완료·취소, 목양지 확인 완료·작성 중, 공지. 제출본 수정으로 version이 증가하면 다시 미확인으로 포함된다.

하나의 SQL 문에서 필터·유형별 개수·전체 개수·페이지 선택을 처리한다. 최신순(시간 내림차순, 유형, ID 내림차순)으로 안정 정렬하고 페이지당 5개다. 12건은 5·5·2개와 3페이지이며, 마지막 항목 처리 후 과거 페이지 번호를 요청하면 새 마지막 페이지로 보정한다. 미처리 0건은 빈 배열과 1페이지로 응답한다.

응답은 `recentActivity`, `activityPagination`(page/pages/total/pageSize), `counts`(prayer/visits/reports). 활동 항목은 종류·간단한 표시명·관리자 상세 링크·접수/제출 시각만 포함한다. 기도 본문·심방 사유·목양지 입력/첨부는 SQL에서 조회하지 않는다. 응답은 private/no-store이며 실패는 본문이나 DB 오류를 노출하지 않는 일반 오류로 처리한다.

검증은 가상 자료만 사용한다. 단위 테스트에서 권한·메타데이터 제한을, 일회용 CI PostgreSQL E2E에서 혼합 상태 필터·5개 채우기·마지막 페이지·완료/확인/수정 반영을 검증한다.
