# 공지 이미지 첨부

요청: 관리자가 공지에 이미지를 첨부하고 회원이 공지를 열면 이미지 → 두 줄 간격 → 본문 순서로 읽는다.

## 구현

- 한 장 선택, 미리보기, 교체/제거, 임시저장/발행. 실패하면 입력과 미리보기를 유지한다.
- JPG/PNG/WebP 입력 3MiB, 요청 스트림 3.5MiB 제한. 서버에서 실제 포맷·단일 프레임·50MP 한도를 검증하고 회전 보정/2400px 축소/WebP 변환/메타데이터 제거를 수행한다. 저장은 최대 2MiB.
- 외부 저장소와 인증 키가 없는 현재 환경에서 별도 서버 전용 DB 테이블을 사용한다. 이미지 바이트를 목록/상세 JSON에 넣지 않고 인증된 이미지 경로로 제공한다. 향후 이미지 양이 늘면 객체 저장소로 이전할 수 있다.
- 공지와 첨부는 트랜잭션으로 함께 저장한다. 수정 시 행 잠금, 이미지 생략 시 보존, 명시적 제거, 삭제 cascade를 지원한다.
- 초안 이미지 비공개, 회원/관리자 권한, private 재검증 캐시, 교체 시 새 버전 URL, 비공개로 변경 시 이전 ETag도 거부한다.
- 기존 JSON 작성/수정 API 호환. multipart 줄바꿈은 LF로 정규화한다.
- 회원 이미지는 원래 비율로 화면 폭에 맞추고 본문 앞에 두 줄 높이(3.5em)의 간격을 둔다.

## 검증

- 단위 336개 및 별도 TLS PostgreSQL 연결 검사 3개 통과. 이미지 디코딩/크기/잘못된 파일/EXIF 제거/요청 제한/권한과 캐시 경계를 포함한다.
- lint 오류 0, 기존 경고 2. production build 성공.
- 새 일회용 DB 전체 Playwright 33개 통과. 이미지 흐름은 관리자 실제 파일 첨부/미리보기/저장 실패 후 재시도/초안/발행/교체/텍스트 수정 시 보존/제거/삭제 및 비회원/일반회원 권한을 검증한다.
- 360px 회원 화면에서 실제 이미지 로드, 이미지 아래 본문 두 줄 높이 간격, 가로 넘침 없음 및 스크린샷 확인.
- 독립 코드 리뷰의 Critical/Important 지적 없음. 메타데이터 제거 테스트가 EXIF를 실제로 가진 입력을 사용하도록 보완했다.
- 실회원 공지/일정은 검증용으로 생성하거나 수정하지 않았다. 원격 배포 검증은 PR 체크에 기록한다.
