# 관리자 제어와 별도 리더 명단

기준 커밋: `e694fb885a23b8edb0959b2c53afe69bbdbaf2a3`. 작업 브랜치는 `feature/prayer-one-month-challenge`, PR #1이며 main에는 병합하지 않는다.

## 변경

- 특정 날짜 활성/비활성 예외, 중복 신청·과거·Calendar 장애 차단 유지.
- 별도 리더 XLS/XLSX 가져오기/수정, 회원 명단 보존, 샘/리더를 사용한 Google 일정 제목·설명.
- 심방 삭제의 Google 선삭제/실패 보존, 초기 생성 중 취소 방지, 기도요청 삭제.
- 해당 도전에 한정한 참여자 명단·통계 제외, 계정·개인 체크인 보존.
- 일요일 시작 달력, 기도 체크 저장 무한 대기 해제와 같은 의도 재시도.

## 검증

- `npm test`: 292개 통과. DB 전용 3개는 별도 일회용 PostgreSQL 17/TLS 환경에서 모두 통과.
- `npm run lint`: 오류 0, 기존 경고 2. `npm run build` 통과.
- 일회용 DB를 새로 생성해 전체 Playwright 22개 통과, 건너뜀 0. 360px 설정 화면, 리더 가져오기와 회원 명단 불변, 심방 삭제, 기도요청의 확인 취소/실패/timeout/재시도, 참여자 제외 후 상세·허브 통계 및 로그인·개인 기록 유지 포함.
- 브라우저 최초 검사에서 Next.js route announcer와 앱 오류 알림이 함께 선택되는 테스트 선택자 문제를 확인하고 main 내부 알림으로 한정했다.
- 독립 코드 검토에서 일정 생성 중 취소 후 삭제하면 Google 일정이 남을 수 있는 경우를 재현했다. event ID가 있으면 항상 Google 삭제를 시도하고, 초기 생성 중 상태 변경을 막았다. 회귀 2개 red→green 확인. Google 404는 실패, 410만 멱등 성공을 유지한다.
- Supabase에 추가형 migration 적용. 사용자 제공 35개 샘 리더 매핑을 별도 sams 테이블에 저장하고 35개 모두 정확히 일치함을 확인. 실제 이름은 저장소에 넣지 않았다. 기존 성도 명단은 수정하지 않았다.
- 새 제외 테이블 RLS 활성, anon/authenticated CRUD 권한 없음. Security Advisor 오류/경고 0, 서버 전용 테이블에 정책이 없다는 INFO 1건은 의도한 차단 상태다.

실제 운영 사용자의 기도요청/심방을 생성하거나 삭제하는 검증은 하지 않았다. 기존 Google 일정을 일괄 변경하지 않는다. Vercel 로그인 요구는 공유 Preview 주소의 Deployment Protection 설정으로 별도 처리한다.
