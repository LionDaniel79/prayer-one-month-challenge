# 접수 이메일 알림 설계

## 목표
새 목양지·심방신청·기도요청이 정상 저장되면 관리자 본인의 Gmail로 샘·이름 및 심방 날짜·시간만 한 문장으로 알린다. 본문, 기도제목, 심방 사유, 연락처, 첨부파일은 이메일과 발송 대기열에 복사하지 않는다.

## Google 연결
기존 Google OAuth Client와 기존 callback 경로를 사용하되, mail. 접두사의 별도 state·PKCE·관리자 세션·일회용 만료 상태로 Gmail 승인을 구분한다. Gmail 권한은 openid/email/gmail.send만 요청하며 받은편지함 읽기 권한은 없다. ID 토큰을 검증하고 관리자에게 저장된 수신 주소와 같은 계정만 연결한다. Calendar refresh token은 읽거나 수정하거나 폐기하지 않는다. 명단 암호화 키에서 용도를 구분한 키를 파생해 Gmail refresh token과 PKCE 값을 비공개 DB에 암호화한다.

Google의 사용자 동의는 개발 도구의 Gmail 연결로 대신할 수 없다. 배포 후 운영자가 Gmail API 사용 설정 및 메일 보내기 권한 승인을 한 번 완료해야 한다. 연결 확인용 가상 메일이 수락된 뒤에만 자동 알림을 켠다. 수신 주소 실값은 공개 저장소에 하드코딩하지 않는다.

## 발송
비공개 트랜잭션 대기열과 완료 시점 DB 트리거를 사용한다. 목양지는 최초 완료, 기도요청은 새 접수, 심방은 Calendar 동기화가 성공한 최초 요청만 대상으로 한다. 초안·실패한 심방·기존 자료·수정·삭제는 새 접수 메일을 만들지 않는다. 동일 종류와 원본 ID는 한 번만 대기열에 등록한다.

Next.js after로 응답 이후 발송을 시도하고 Supabase pg_cron/pg_net이 전송 대기 건이 있을 때에만 보호된 Production 엔드포인트를 호출한다. 예약 호출 비밀값은 Vault에 보관하고 앱에는 해시만 저장한다. 발송 대기열은 잠금·임대·횟수 제한을 사용한다. 명확한 임시 거부만 재시도하며 Gmail 수락 여부를 알 수 없는 타임아웃/서버 오류는 중복 위험 때문에 unknown으로 보류한다. 외부 서비스의 정확히 한 번 배달을 보장한다고 표현하지 않는다. Gmail 장애가 이미 성공한 원본 제출을 실패로 바꾸지 않는다.

## 관리 화면과 자료 수명
대시보드 맨 아래 접을 수 있는 이메일 알림 패널에서 수신 주소, Gmail 연결, 사용 여부, 확인 메일, 연결 해제와 간단한 상태를 관리한다. 별도 설정 메뉴는 되살리지 않는다. Production에서만 설정 변경·실제 발송이 가능하다. 알림 해제·수신자 변경·원본 삭제 시 아직 보내지 않은 본문을 정리한다. 완료 메타데이터는 30일, 완료 알림의 최소 내용은 7일 이내 정리하며 7일 넘은 미발송 건도 취소한다. 앱에서 연결 해제는 메일 자격증명만 지우며 Google 전체 동의 취소는 Calendar에도 영향이 있을 수 있음을 설명한다.

## 검증 및 배포
본문을 포함하지 않는 정확한 한글 문구, MIME 주입 방지, 용도별 암호화, OAuth 계정/권한/state 검증, 관리자 및 동일 출처 경계, 전송 성공/명확한 거부/불명확 결과, 원본 완료/취소 트리거, 모바일 패널을 검증한다. 실제 성도 자료로 시험 로그인·목양지 작성·삭제하거나 실제 계정에 시험 메일을 임의 발송하지 않는다. 일회용 DB와 가상 Gmail 응답으로 전체 검사를 통과한 뒤 추가형 마이그레이션·예약 작업·Production을 적용한다. 최종 보고에서 앱 배포와 사용자의 Gmail 승인/실제 수신 확인을 구분한다.
