# 관리자 대시보드 집계·목양지 확인·페이지 이동 구현 계획

> 실행: 기존 feature/admin-dashboard-metrics 브랜치의 검증된 e1f9ad6 소스를 이어 사용한다. 사용자 요청에 따라 중간 승인 없이 구현·검사·정식 배포까지 진행한다.

**목표:** 사용자 활성화와 기도 참여를 분리하고, 목양지 미확인과 최근 활동을 관리자가 정확히 확인한다.
**구조:** 최초 로그인 기록과 목양지 확인 버전만 추가한다. 기존 로그인 허용 여부/원문/파일/기간/Google 비밀값은 변경하지 않는다. 최근 활동은 DB에서 최신순(동률은 종류·ID로 정렬), 10개 단위로 조회한다.
**기술:** 기존 Next.js, Drizzle/node-postgres, Supabase, Vitest/Node test, Playwright/일회용 TLS DB 및 Vercel Production.
**요구 기준:** 사용자 최신 10개 항목 및 앞서 요청한 공지 우선 메뉴·전체 사용자 기도 탭 표시 설정.

## 완료 기준 및 파일
- [ ] `users.first_login_at`를 세션 생성과 같은 트랜잭션에 기록. 기존 세션의 최초 날짜로만 이관하고, 로그인하지 않은 사전 생성 계정은 활성으로 오인하지 않는다. `roster-service.ts`, `session.ts`, `schema.ts`.
- [ ] 전체 등록은 현재 성도 명단, 활성은 그 명단 중 한 번 이상 로그인. `is_active`는 기존 로그인 허용 플래그로 유지하며 화면에는 별도 ‘로그인 제한’으로 표시. 사용자 관리 필터·배지·안내를 활성/비활성으로 통일.
- [ ] 목양지에 확인 버전/확인자/시각을 추가. 완료본만 관리자 명시적 POST(동일 출처 확인)로 확인한다. 단순 GET/회원 열람/초안은 확인으로 처리하지 않는다. 오래된 버전 확인은 최신 수정본을 확인하지 못한다.
- [ ] 관리자 상세 화면 로딩 성공 후 확인 요청. 새 버전은 다시 미확인, 네트워크 실패는 재시도 안내. 카드 클릭과 최근 활동 링크는 해당 상세/미확인 목록을 연다.
- [ ] 기도 참여자는 활성 도전의 설정 기간·오늘까지 유효한 월~토 체크가 한 번 이상인 고유 사용자. 기존 도전별 제외 기능 유지. 대시보드·참여자 명단·샘 통계가 같은 기준 사용.
- [ ] 기도 탭 비활성 시 참여자 명단·샘 통계를 API/화면 모두 반환하지 않음. 설정 저장 즉시 관리 화면도 갱신. 도전 설정과 기록은 보존.
- [ ] 관리자 메뉴: 대시보드 다음 공지 관리, 다음 기도운동 관리. 회원의 공지 우선/기도 탭 전체 설정은 기존 동작 보존.
- [ ] 카드: 활성 사용자·전체 등록 사용자·기도 참여·목양지 미확인·심방 신청 대기·미처리 기도요청. 확정 심방/공지 건수 제거.
- [ ] 최근 활동: 목양지 완료 제출 포함, 원문/파일명/사유를 목록으로 노출하지 않음. 10개씩, 최신 첫 페이지, 이전/다음 및 페이지 선택, 빈 목록·잘못된 페이지·동일 시각 처리.
- [ ] 기존 날짜 의존 검사 2개는 고정 기준일을 전달해 시간 경과로 실패하지 않도록 보정(서비스 정책 자체는 변경하지 않음).
- [ ] 테스트 실패 재현 → 정책/계약/DB/브라우저 검사 → 변경 검토 → 비파괴 DB 적용 → main 병합 → 정확한 Production SHA·공개 접근 검사.

## 집중 회귀 검사
로그인만 한 사용자와 체크한 사용자가 분리됨. 초기 관리자 사전 생성은 비활성, 실패 로그인은 집계 불변. 로그아웃 후에도 활성 기록 유지. 다른 도전·기간 밖·일요일·미래 체크는 참여자로 세지 않음. 숨김 시 서버와 이미 열린 관리 화면에서 개인정보 목록 숨김. 초안 제외, 회원 확인 API 거부, 같은 버전 재확인 멱등, 이전 버전 확인 거부. 23건이 10/10/3으로 중복 없이 정렬. 실제 사용자 자료는 시험 수정하지 않음.
